# i-Clusters 3.1.0-rc.3

21 October 2026 · Developer: **The Adekola** · Company: **ATT-Tech**

This release candidate improves pending-report wording and adds deliberate manual alert resolution. The [previous candidate](v3.1.0-rc.2.md) deployment and acceptance boundaries still apply.

- Pending overview/provider/report summaries display **Loading…** without a spinner. Completed unavailable readings remain Unknown; measured values, including zero, are preserved during refresh.
- Operators, admins and owners can acknowledge an alert, then select **Resolve** beside Acknowledge in its details. The alert leaves active counts and remains in history with the resolver, time and manual origin. Viewers cannot change alert state.
- Manual closure does not verify that a host, connection or backup destination has been repaired. It does not emit a measured-recovery notification; unsent alert retries are cancelled. A later monitoring observation of the same failure can create a new alert. An older in-flight observation cannot undo manual closure.
- API clients now use `POST /api/alerts/:id/acknowledge` for acknowledgement. `POST /api/alerts/:id/resolve` requires an acknowledged alert and performs manual resolution. Refresh older browser tabs after upgrading.

The CI gates include UI/API regressions, production build, isolated deployment, encrypted controller recovery and vulnerability scans. Live installation/device acceptance remains separate; see the [acceptance checklist](../acceptance-checklist.md).

Before upgrading, preserve an encrypted off-host controller backup and finish or recover active installations. Tracking-branch installations can run `sudo homecloud update`; pinned installations need an explicitly selected release.
