# i-Clusters 3.1.0-rc.2

21 October 2026 · Developer: **The Adekola** · Company: **ATT-Tech**

This candidate corrects report-loading and Docker update-check latency. It retains the deployment and acceptance boundaries of [3.1.0-rc.1](v3.1.0-rc.1.md).

## Changes

- Page reads, sign-in and token refresh have 30-second response deadlines, including response-body consumption. Ordinary actions allow two minutes. Existing synchronous guest provisioning and image build/pull paths allow 17 minutes. A timeout does not prove a submitted operation stopped; inspect its result before retrying. No timeout automatically resubmits a write.
- Docker registry scans use rolling work, limited to four image checks globally within a scan and two per Docker host. Completed results become visible immediately. Local-image reads allow ten seconds and registry requests fifteen seconds, with one bounded retry for transient failures. The registry phase has a two-minute overall budget. Unfinished checks report unknown and cannot clear existing update alerts.
- Docker check status polls every two seconds while active and returns to normal quiet polling when complete. Installation progress remains independent.
- The terminal implementation downloads only when opened. Authentication/approval handling remains available on every authenticated page.

## Verification and limits

Regression coverage includes stalled connections/bodies, caller cancellation, non-retried mutations, rolling registry work, scan expiry, retained alerts, adaptive polling and terminal behavior. CI also runs deployment, encrypted controller restore and vulnerability gates. Consult the workflow for exact results.

The earlier main-branch CI API probe measured p95 46.7 ms across 80 requests at concurrency eight on an **empty-provider** controller. A synthetic blocked-fleet monitoring-function probe returned partial data at p95 251.8 ms across 20 samples. Neither measurement includes live customer providers or browser rendering. The attempted live dashboard inspection was blocked by a certificate common-name mismatch; no certificate validation was bypassed.

Ordinary monitoring remains scheduled every 30 seconds by default. Page refresh settings and collection duration affect freshness; these changes do not claim instant provider measurements or faster image downloads. [Customer acceptance](../acceptance-checklist.md), real-device/load testing and independent security review remain necessary before general availability.

## Upgrade

Take an encrypted off-host controller backup and finish or recover active installations, then run `sudo homecloud update` on a tracking-branch installation. Pinned installations require an explicitly selected release. Confirm the version under Settings → About and validate the configured providers afterward. See the [release policy](../release-policy.md) and [recovery guide](../../deployment/SECURITY-AND-RECOVERY.md).
