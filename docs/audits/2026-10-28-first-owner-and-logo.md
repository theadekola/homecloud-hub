# First owner registration and product logo

First-use owner registration no longer requires a setup code or SETUP_TOKEN environment value. The first valid registration creates the owner. Registration still checks for existing users under the existing exclusive database table lock, rolls back subsequent attempts, hashes passwords and uses the existing registration rate limiter. Password length, username validation, active owner creation and the return-to-sign-in flow remain unchanged. Existing accounts and their sign-in behavior are preserved. Before the first owner exists, anyone who can access the registration page can claim ownership; the installer, UI and deployment documentation explain this behavior.

The installer and upgrade path no longer generate setup codes. Database and session signing secrets remain generated. Existing legacy SETUP_TOKEN entries can remain in .env but are unused. The deployment registration smoke script now exercises registration without a token and retains its competing-registration check for real PostgreSQL CI.

The existing product PNG files decode correctly locally. The screenshot's broken separate image request cannot be diagnosed further without the live HTTP response. The registration/sign-in, sidebar and About pages now use a shared data URL containing the existing 192-pixel logo, eliminating that separate image request. No new artwork was created. The production CSP already permits data images.

Validation: API registration fixtures check password hashing, validation, lock-before-insert ordering, closure and rollback. Login UI fixtures verify four-field registration and no setup-token payload. A brand asset check compares the embedded bytes to the original PNG. A fresh secrets-generator smoke test confirms no setup token and retained database/session secrets. The production bundle was checked for the exact embedded PNG. Shell syntax, full API/web tests and production build are checked before merge. No live user VM, PostgreSQL Compose stack or physical iOS browser was used.
