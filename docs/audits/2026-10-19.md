# HomeCloud code and automated audit, 19 October 2026

Scope: current main at 91ec884, API and browser tests, production build, dependency advisories, deployment scripts, and source review of authentication, role checks, reporting/cache behavior, monitoring/notifications, backups/storage, connectors, and Docker update jobs.

## Corrections

- Mounted reports now immediately revalidate after a successful write invalidates a pending read. Previously, the aborted initial request could leave a report empty until polling or a manual refresh, indefinitely for views without polling. Shared requests remain deduplicated and late responses cannot overwrite current data.
- Docker update recovery now accounts for mutations applied before a response is lost. It inspects the original container, repairs attempted policy/stop/rename/network changes, and verifies identity, image, name, running state, restart policy, network membership, aliases and explicit addresses before reporting recovery. Unverifiable restoration is reported as incomplete. Mounted volumes are not deleted.
- Inaccessible installation progress (401/403/404) now unlocks the popup and explains that the background job may still be running. Unknown results cannot trigger a duplicate installation from the review.

Regression coverage includes interrupted initial reads, lost responses after four Docker mutation types, falsely successful restoration responses, and lost access to a background job.

## Validation

- Full API and browser test suites and production build.
- Deployment updater and network shell tests, HTTPS configuration tests, and Python node-agent tests.
- npm advisory audits: API production dependencies and web dependencies including development packages reported zero known vulnerabilities at audit time.
- The production build retains a large JavaScript chunk warning. This is a performance opportunity, not a build failure.

## Limits and installation checks

This audit does not establish that every possible error is absent. No access to the private Proxmox, Docker, TrueNAS or notification destinations was available. Provider inventory, credentials, mount availability, actual update downloads, notification delivery and backup restoration require installation checks.

After deployment, verify report navigation and refresh, acknowledge an alert and confirm its badge decreases, review an update through completion, and run a backup job to the shared destination followed by a test restore. Writable shared storage alone does not demonstrate a completed backup. Inactive media-storage is a separate infrastructure condition; do not bypass its mount-point protection or import a disk owned by a running TrueNAS guest on the Proxmox host.
