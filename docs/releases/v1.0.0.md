# i-Clusters v1.0.0

Release-notes baseline: 29 October 2026 · Developer: **The Adekola** · Company: **ATT-Tech**

The i-Clusters release series starts at **v1.0.0**. Application and package metadata use **1.0.0**. This document defines the first numbered release baseline; it does not claim that a GitHub release has been published or that production acceptance is complete. Release publication remains paused under the [release policy](../release-policy.md).

## Included functionality

- A responsive infrastructure dashboard, monitoring, measured alert rules, activity history and configured external notifications.
- Proxmox VE inventory and supported VM/CT creation, lifecycle, storage, network, backup, restore and task workflows, with role checks and action approvals.
- Paired Linux Docker hosts and Proxmox node connectors, supported container/image/network/volume management, image update checks and recoverable replacement workflows.
- TrueNAS pool, disk, dataset, snapshot and share integrations, with version-dependent API compatibility.
- Verified SSH access, multi-tab terminals and SFTP; automatic connector setup with separate SSH and required guest-restart popups.
- Owner-selected OpenAI, Claude, Gemini, DeepSeek, Groq or Mistral configuration, matching model choices and read-only AI assistance.
- MFA, recovery codes, revocable sessions, encrypted integration configuration, controller backup/restore and upgrade rollback tooling.

## Corrections included in this baseline

- Consistent page paths, tab headings, mobile layouts and visible pending/refresh indicators.
- Software update review and installation in a popup, with progress and reconnection feedback.
- SSH fingerprint eye icons beside identity headings, plain Docker host names and a direct Connect TrueNAS action.
- Storage inventory excludes registrations assigned only to other nodes while retaining applicable offline storage.
- Caddy is rebuilt with patched go-jose v4.1.6 and x/net v0.60.0 dependencies. CI verifies the running binary's dependencies and scans runtime images.

## Installation and upgrades

Follow the [installation guide](../../README.md) and [deployment instructions](../../PRODUCTION.md). Tracking-branch installations use `sudo iclusters update`. A pinned `--ref v1.0.0` installation is possible only after that tag is published; verify the tag exists first. Preserve encryption keys, keep an encrypted off-host backup and finish or recover active operations before upgrading. Renumbering does not reset accounts, provider connections, data or build revision identifiers.

## Scope and release status

Use one controller per installation. Supported versions and operations need [compatibility acceptance](../compatibility.md), actual restore and interrupted-update checks, physical-device/load testing and independent security review before general production approval. See the [acceptance checklist](../acceptance-checklist.md), [security policy](../../SECURITY.md), [privacy policy](../../PRIVACY.md), [terms](../../TERMS.md) and [MIT licence](../../LICENSE).

Earlier 3.x release-candidate notes remain as historical development records. Existing remote releases, tags and assets are preserved; they are not relabelled as v1.0.0.
