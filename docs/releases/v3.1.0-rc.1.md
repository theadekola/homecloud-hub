# i-Clusters 3.1.0-rc.1

20 October 2026 · Developer: **The Adekola** · Company: **ATT-Tech**

This release candidate adds self-service account security and recoverable installation workflows. It is intended for controlled evaluation on separate customer controllers. General availability, shared SaaS isolation, guaranteed uptime and universal provider compatibility are not claimed.

## Highlights

- Users can enable authenticator MFA under Settings → Security, save ten one-time recovery codes, change passwords and revoke signed-in devices.
- Explicit logout invalidates the current server session. Supported browsers use Secure HttpOnly refresh cookies, with a fixed ten-day remembered deadline.
- Docker installations retain encrypted progress/checkpoints across controller restarts. Interrupted recovery is exclusive, blocks duplicate installation, and verifies the recovered container's identity, state, policy and networks.
- Software and Docker installation screens request a wake lock while visible. Device/browser policy may release it; jobs do not rely on the display staying awake.
- Controller backup/restore tools preserve database, runtime, encryption keys, local HTTPS authority and offline Git history. Upgrades retain a consistent local recovery point and attempt rollback after failed health checks.
- The current UI, package metadata and first-party documentation identify The Adekola as developer and ATT-Tech as company. Third-party credits and licence notices are retained.

## Upgrade

1. Finish or recover active Docker updates, and take an encrypted off-host controller backup. Retain the private backup identity separately.
2. Review these notes and run `sudo homecloud update` for a tracking-branch installation. The first upgrade from older code follows that older installed CLI's procedure; the new rollback flow is available after this update.
3. Open the HTTPS address, confirm version 3.1.0-rc.1 under Settings → About, and test login, provider reads, alerts and backups. Update paired connectors where offered.
4. Users may opt into MFA. Save recovery codes outside the controller before leaving enrollment. Existing passwords/account identities are retained.

Pinned/tag installations require an explicit reviewed ref change; the CLI does not silently move a detached release checkout. See [release policy](../release-policy.md).

## Evidence supplied by CI

The release workflow must pass API/UI regressions, production build, isolated Compose deployment, real PostgreSQL authentication/MFA/revocation, encrypted controller restore and restored sign-in. Upgrade rollback has isolated command fixtures; container vulnerability scans and npm advisory scans are separate gates. Component inventories, image identities, scan reports and checksums accompany the published candidate. Check the linked workflow for the exact test count and scan time. Checksums detect corruption; they are not signatures or independent security certification.

## Remaining acceptance

Live fresh-guest restore/data verification, exact provider/guest-OS combinations, physical mobile/desktop behavior, measured customer fleet capacity, RPO/RTO and independent authenticated security assessment remain installation-specific work. Record results in the [acceptance checklist](../acceptance-checklist.md). Container application-data migrations cannot be undone by replacing an image. No shared multi-tenant controller is supported.
