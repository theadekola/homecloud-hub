GET UP AND RUNNING

Your lab. Your server. Your rules.

Run i-Clusters on a dedicated Ubuntu server or VM. The installer sets up the required services and prints the local HTTPS address for your browser.

1

Prepare a dedicated Ubuntu server or VM with network access.

2

Review the installer script, then run it with administrative access.

3

Sign in to your controller and connect supported providers.

Read the full installation guide ↗
ubuntu · terminalQuick start

# 1. Install curl

sudo apt-get update
sudo apt-get install -y curl

# 2. Download and review the installer

curl -fsSL https://raw.githubusercontent.com/theadekola/i-clusters/main/install.sh -o /tmp/iclusters-install.sh
less /tmp/iclusters-install.sh

# 3. Run the reviewed installer

sudo bash /tmp/iclusters-install.sh

GOOD TO KNOW

A few things worth asking.

Looking for exact setup requirements or feature support? The repository documentation is the source of truth.

Browse documentation ↗
Is i-Clusters really free to use?+

Yes. Its source is published under the MIT licence. Hosting your own server and using optional third-party services may have their own costs.

Does it need an external cloud account?+

The controller runs on your own Ubuntu server or VM. It connects to infrastructure you configure. Optional notifications and AI features can use external services only when you configure them.

What can I connect today?+

The documented integrations are Proxmox VE, paired or optionally direct Docker hosts, and TrueNAS. Supported operations vary by provider version, permissions and connection configuration.

Can I use it in production?+

The current version is a release candidate for controlled evaluation. A customer-specific acceptance process, real backup/restore tests, provider verification and independent security review are still required before treating it as production-ready.

Where do I report issues or contribute?+

Use GitHub Issues for bugs and feature requests and read CONTRIBUTING.md before submitting changes. Please do not share passwords, tokens or sensitive logs in public issues.
